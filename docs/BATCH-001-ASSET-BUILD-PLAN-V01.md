## 3. Derivative Asset Rule

Each learning prop gets:

1. design brief
2. canonical-style generation
3. front view
4. side view
5. top/3-quarter view where useful
6. interaction view where useful
7. QA
8. asset ID
9. approved version
10. reuse map

## 4. Asset Naming

`RERE-PROP-[CATEGORY]-[NAME]-V01`

Examples:

`RERE-PROP-COLOR-APPLE-01`

`RERE-PROP-NUMBER-CARD-01`

## 5. Reuse Matrix

Before creating a new object, search this plan and the Canonical Asset Registry.

| Question | Action |
|---|---|
| Existing canonical asset? | Reuse |
| Existing approved derivative? | Reuse |
| Similar but not identical? | Evaluate identity need |
| New recurring object? | Create derivative + approve |
| One-shot decorative object? | Generate only if necessary |

## 6. Asset Approval

An asset becomes reusable only after:

- visual QA
- scale QA
- interaction QA
- continuity QA
- child readability QA
- explicit status assignment

## 7. Batch Efficiency Target

Aim for approximately:

**1 canonical/approved asset → multiple shots → multiple episodes**

Do not optimize for the fewest generated images; optimize for the fewest unique identities that still create varied stories.
