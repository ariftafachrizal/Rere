# RERE — PROJECT ROADMAP EP001–EP120 V02

**Scope:** EP001 through EP120  
**Current production batch:** Batch 001 / EP001–EP006  
**Status:** Long-range roadmap locked as working scope

## Production rule

The project proceeds episode-by-episode. No storyboard is changed after its production lock unless a separate explicit project decision is made.

Each episode follows:

1. Reference freeze
2. Gemini/reference package preparation
3. Generation or approved asset reuse
4. Visual QA and continuity QA
5. Voice/audio production
6. Editing and master QA
7. Thumbnail/title/packaging
8. Final publish gate
9. Publish
10. Post-publish learning review

## Expansion roadmap

### Phase A — EP001–EP006
Batch 001 production and validation. Establish the repeatable end-to-end production system.

### Phase B — EP007–EP036
Continue the same controlled production system episode-by-episode. Do not treat future episodes as storyboard-locked until their content, storyboard, references, prompts, and QA gates are explicitly prepared and locked.

### Phase C — EP037–EP120
After EP036 is completed and the system has been validated, continue the same production-control system through EP120. Future episodes must be generated from the canonical learning framework, character/world/prop systems, production templates, and QA standards. Each episode receives its own content lock, storyboard lock, reference package, generation pack, QA gate, and publishing package before execution.

## Shorts rule

Baseline remains **5 Shorts per long-form episode**, unless a later explicit project decision changes the baseline. Shorts are derivatives of approved long-form learning moments by default: reuse/crop/reframe to 9:16 first, with dedicated vertical generation only when crop/reframe fails QA.

Therefore the long-range baseline is:

- EP001–EP120: 120 long-form episodes
- Shorts baseline: 600 Shorts
- Total planned video outputs: 720

This is a production-planning baseline, not a claim that all future assets have already been generated or locked.

## Autonomous execution principle

The repository and Todoist must contain enough operational information for downstream execution in Gemini without requiring the owner to return to ChatGPT for routine production decisions.

For every episode, the production package should provide:

- canonical references
- locked content/script
- locked storyboard
- asset mapping
- Gemini prompt package
- generation runbook
- shot-level instructions
- voice/audio instructions
- editing template/instructions
- thumbnail/title/packaging guidance
- QA acceptance criteria
- publishing checklist
- post-publish learning review

Routine execution should therefore be possible from **Todoist + GitHub → Gemini → human QA → publishing**, without conversational approval for already-decided production rules.

## Control principle

Do not optimize for speed by weakening canonical consistency, child-safety QA, learning clarity, or production traceability.

**Value order:** Value → Trust → Audience → Scale → Revenue.

## Definition of long-range readiness

EP120 is considered system-ready only when its production resources are present and internally consistent in the repository and corresponding actionable work is represented in Todoist. A future episode must never be marked complete merely because its planning placeholder exists.
