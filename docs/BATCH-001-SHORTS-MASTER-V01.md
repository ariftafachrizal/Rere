## 1. Purpose

Batch 001 menggunakan satu production system untuk menghasilkan dua format:

1. **YouTube Long-form** — episode utama.
2. **YouTube Shorts / vertical short-form** — potongan pendek yang dirancang sebagai standalone learning content, bukan sekadar crop otomatis dari long-form.

Shorts harus tetap mengikuti seluruh canonical system Rere: character, world, props, voice, learning framework, camera, lighting, editing, QA, dan packaging.

## 3. Shorts Design Principle

A Short must answer one simple question:

> **Apa satu hal yang bisa dilakukan / dikenali / diucapkan anak setelah menonton Short ini?**

Principles:

- one Short → one clear learning idea
- one action at a time
- child participation before answer reveal
- visible pause / wait time where appropriate
- Rere remains a learning companion
- no context that requires watching the long-form first
- no misleading educational claims
- no overstimulation solely to increase retention
- no identity drift
- no random prop or environment redesign

Recommended duration: **15–45 seconds**. Extend only when the learning interaction genuinely needs more time.

---

## 4. Standard Short Architecture

### A. Hook — 0–3s
Immediate visual/question/action.

### B. Learning interaction — 3–20s
Rere introduces one object, concept, action, or problem.

### C. PAUSE — 2–5s
Child gets time to answer, point, imitate, count, match, or act.

### D. Reveal / reinforcement — 20–35s
Rere confirms the answer and gives positive reinforcement.

### E. Micro close / CTA — final 2–5s
Optional. Keep secondary to learning. Where appropriate, point toward the full episode without making the Short dependent on it.

Timing is flexible. The learning interaction takes priority over arbitrary duration targets.

## 5. Canonical Short IDs

Naming convention:

`RERE-B001-EP###-SH##`

Examples:

- `RERE-B001-EP001-SH01`
- `RERE-B001-EP001-SH05`

File naming should preserve the same ID across script, storyboard, Gemini prompt, generated assets, edit project, master render, thumbnail/frame, QA record, and publishing metadata.

## 13. Vertical Composition Rules

- Design for 9:16 first when a Short is specifically generated as a new shot.
- Keep Rere's face and key learning object inside a safe central area.
- Avoid placing critical learning content at extreme top/bottom UI zones.
- Prefer medium/close framing for object recognition.
- Use wider framing only when the child's action or environment is itself the learning target.
- Do not crop canonical anatomy, props, or learning objects in a way that changes meaning.
- Use the canonical character reference; vertical framing is not permission to redesign Rere.

---

## 14. Reuse Rules

A Short may reuse an approved long-form shot when:

- the source shot already communicates the learning idea clearly;
- vertical crop does not damage identity or learning clarity;
- dialogue/audio can be edited cleanly;
- pause timing remains usable;
- no additional generation is needed.

Generate a dedicated vertical shot when the crop would compromise learning clarity, character identity, object visibility, or action readability.

**Reuse is preferred over unnecessary regeneration.**

## 15. QA

All Shorts use `docs/BATCH-001-QA-SYSTEM-V01.md`.

Additional Short checks:

1. 9:16 composition works.
2. Hook is understandable without long-form context.
3. One clear learning target.
4. PAUSE is visible/audible and long enough for age 2–4.
5. Correct answer is unambiguous.
6. Rere identity remains canonical.
7. Learning object/prop remains canonical.
8. Voice is clean and consistent.
9. No text/UI artifact obscures the learning target.
10. Short does not feel like an arbitrary clip dump.

P0/P1 failures remain automatic reject conditions.

---

## 16. Publishing Strategy

Shorts are a discovery/distribution layer, not a replacement for the main episode.

Recommended relationship:

**Long-form = primary learning experience**  
**Shorts = focused micro-learning + discovery**

Each Short should have its own title/hook and should stand alone. Where useful, metadata can reference the related full episode.

Publishing cadence is intentionally left flexible until the first batch is produced and reviewed.
