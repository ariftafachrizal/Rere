# RERE — CHANNEL FOUNDATION MASTER V01

**Status:** ACTIVE / CANONICAL  
**Date:** 2026-09-14  
**Purpose:** Build the Rere YouTube channel as a real operating property before episode production begins.

## 1. Objective

Create the complete minimum viable channel foundation for Rere so that the project has a real home, recognizable identity, controlled publishing configuration, and a repeatable operating system.

This master sits **upstream of** `docs/RERE-PRODUCTION-CONTROL-MASTER-V02.md`.

## 2. What “house is ready” means

The Rere house is ready when the following are true:

- YouTube channel exists and is controlled by the project owner.
- Channel name and handle are locked.
- Avatar and banner are ready and uploaded.
- Channel description is approved.
- Channel audience/content settings are configured appropriately for children's content.
- Channel homepage and playlists have an intentional structure.
- Upload metadata templates exist.
- Thumbnail/title conventions are documented.
- Publishing QA checklist exists.
- Analytics baseline and review process exist.
- GitHub and Todoist responsibilities are clear.
- EP001 can be handed from production into publishing without inventing a new process.

## 4. Channel identity lock

Do not create multiple public identities for Rere. The character and channel should read as one coherent brand.

Canonical brand source:
- `docs/BRAND-GUIDELINE.md`
- `docs/CHARACTER-BIBLE-RERE.md`

Channel-facing assets may adapt the canonical identity for YouTube formats but may not redesign Rere's identity.

## 5. Audience model

Primary viewer:
- Children ages 2–4 during the first six months.

Primary decision maker:
- Parents/caregivers.

The child should experience:
- play
- curiosity
- participation
- repetition
- positive reinforcement

The parent should be able to understand:
- what the child is learning
- why the activity is appropriate
- that the environment is safe and age-appropriate

## 6. Channel content architecture

### Long-form

Purpose: deeper learning interaction and repeatable episode experience.

Default:
- 16:9
- approximately 3–4 minutes for initial episodes
- Indonesian spoken master
- story → discovery → question → PAUSE → response → reinforcement → repeat

### Shorts

Purpose:
- discovery
- focused micro-learning
- entry point to Rere
- testing hooks and interaction patterns

Default:
- 9:16
- 20–40 seconds preferred; 15–45 seconds acceptable
- derived from approved long-form where possible

## 7. Playlist architecture

Initial playlist families should remain simple and understandable. Recommended structure:

1. **Mulai Belajar Bersama Rere** — entry point / strongest introductory episodes
2. **Belajar Konsep Dasar** — colors, shapes, numbers, matching, size, position
3. **Bahasa & Bicara** — SPEAK / language activities
4. **Perasaan & Berteman** — FEEL / social-emotional learning
5. **Kebiasaan Baik** — LIVE / routines, manners, independence
6. **Kreasi & Imajinasi** — CREATE
7. **Rere Shorts** — short-form discovery content

Playlist names can be refined after actual channel behavior is observed, but the hierarchy must remain child/parent understandable.

## 8. Publishing metadata system

Every published episode must have a metadata record containing:

- episode ID
- final YouTube title
- description
- hashtags
- primary pillar
- learning promise
- target age
- content type
- playlist destination
- thumbnail reference
- long-form filename
- Shorts filenames
- publication date/time
- final QA status

The episode production card remains in Todoist; the durable metadata record belongs in GitHub.

## 9. Publishing gate

Never publish because an export exists.

Required:

**Production complete → Final QA → Metadata ready → Thumbnail ready → Playlist selected → Upload → Settings checked → Preview → Publish/Schedule → Record publication → Analytics baseline created.**

## 10. Channel safety

Rere is children's educational media. Channel-facing decisions must preserve:

- child-safe language
- non-shaming interaction
- no unsafe demonstrations
- no unnecessary fear
- no misleading educational claims
- no exploitative engagement mechanics
- no copyrighted third-party character dependence
- no random identity drift

## 11. Operating loop

**PLAN → PRODUCE → QA → PACKAGE → PUBLISH → MEASURE → LEARN → IMPROVE**

GitHub stores the rules and durable records. Todoist stores actionable work. YouTube stores the public output and platform analytics.

## 12. Handoff to production

Once foundation readiness is complete:

1. Open `docs/RERE-PRODUCTION-CONTROL-MASTER-V02.md`.
2. Start at `00 — START HERE`.
3. Execute EP001 as the pilot.
4. Validate the complete production-to-publish loop.
5. Scale only after EP001 passes the pilot gate.

## 13. Handoff to growth

Growth work must not distort the learning promise. Optimize for:

**Value → Trust → Audience → Scale → Revenue.**

The first meaningful optimization target is not maximum upload volume. It is discovering what children enjoy, what parents trust, and which learning formats produce strong completion and repeat engagement.
